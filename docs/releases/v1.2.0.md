# v1.2.0

This release corrects seven defects that made the evaluator return **wrong concept
sets without any error**, and closes the `DataProvider` contract so a third party
can implement it from the godoc.

**No exported signature changed**, so `go get -u` compiles. But eight behaviours
did change, and four of them alter results rather than break the build — read
[Behaviour changes](#behaviour-changes) before upgrading. If you have snapshot
tests over ECL results, expect them to move; that is the point of the release.

The conformance suite went from 44 cases (of which CI ran 8) to **136, all
executed by CI**, plus two suites whose expectations this project did not write:
the **121 official ECL examples** SNOMED International publishes as valid, all of
which parse, and a **differential oracle** that agrees with a real terminology
server on 28 of 29 cases over SNOMED CT.

---

## Behaviour changes

### 1. The parser now rejects input it used to accept

`Parse` invoked the grammar's root rule without requiring the token stream to be
consumed, and never registered an error listener on the lexer. Two consequences,
both now errors:

```go
ecl.Parse("11687002 TOTALGARBAGE")
// was: err == nil, AST = ConceptRef{11687002}   -- the rest discarded
// now: *ecl.ParseError

ecl.Parse("404684003 MINUS 11687002 MINUS 73211009")
// was: err == nil, silently truncated to "404684003 MINUS 11687002"
// now: *ecl.ParseError  (MINUS takes exactly two operands)

ecl.Parse("404684003 |Crohn’s disease|")   // U+2019
// was: err == nil, term "Crohns disease", complaint written to os.Stderr
// now: *ecl.ParseError
```

The third case is the one to watch: `ECL.g4`'s `UTF8_LETTER` ranges start at
U+00C0, so characters in the gaps — U+2019 (typographic apostrophe), U+00B0
(degree sign), U+00A0 (no-break space, which any copy-paste from the SNOMED
browser carries) — are now reported instead of being deleted from the token
stream. Accented Latin letters were always fine and still are: the cut is not
ASCII vs non-ASCII.

**Why an error rather than a normalization.** Rewriting the input would silently
change the term the provider is matched against. Widening `UTF8_LETTER` is the
real fix and needs the generated parser regenerated; until then, reporting is the
honest answer.

**If you validate user input**, expect expressions that used to pass to fail.
Classify them with `errors.As` on `*ecl.ParseError` and show
`pe.Errors[i].Line`/`.Column`.

### 2. Negated description filters now return an error

`{{ D term != … }}`, `{{ D language != … }}`, `{{ D type != … }}` and
`{{ D dialect… != … }}` return `ecl.ErrUnsupportedFeature`.

They used to be computed as `base.Minus(matches)`, which is not the ECL
semantics. A negated description filter selects concepts that **have** a
description failing the comparison — a per-row negation. A concept with both an
FSN and a Spanish synonym satisfies `language != es` through its FSN, yet `Minus`
removes it because it also has a Spanish row.

A classifiable error beats a wrong set. To get these working, implement the
optional `ecl.NegatingDescriptionProvider`, which receives each dimension with its
own polarity so your storage can negate at the row level.

**Negated concept filters are unaffected and now work correctly** — see fix 5.

### 3. `AllConcepts` and `ConceptExists` must no longer filter by `active`

The active axis belongs to `FilterConcepts` alone. This is a **contract
redefinition**: if your provider filters inactive concepts out of `AllConcepts`,
it is now non-conforming.

The wildcard is resolved *before* filters are applied, so an `AllConcepts` that
returns only active concepts makes `* {{ C active = false }}` unable to return
anything, whatever `FilterConcepts` does. It was a structural dead end, not a
documentation slip.

```go
// before: [] no matter what your FilterConcepts did
// after:  the inactive concepts
ecl.Parse("* {{ C active = false }}")
```

### 4. `HistoricalAssociations` runs the other way round

The godoc described it as expanding *inactive concepts to their replacements*.
The spec defines the supplement as

```
(X) OR (^ 900000000000527005 {{ M targetComponentId = (X) }})
```

so the input is the set of (typically active) concepts and the result is the
**historical concepts pointing at them**. Also a **contract redefinition**: a
provider written to the old godoc made `{{ +HISTORY }}` a silent no-op for every
realistic input.

```go
// with a conforming provider:
// before: [22298006]
// after:  [22298006, <the inactive concepts it replaced>]
ecl.Parse("22298006 {{ +HISTORY }}")
```

### 5. Reverse (`R`) attributes: unsupported forms now error

`RelationshipTargets` returns a `Set`, so it loses how many inbound relationships
a concept has and of which types. Every form needing that was answered anyway,
and wrongly:

| Form | What it used to return | Now |
|---|---|---|
| `[m..n] R attr = value` | the same set as without the cardinality — so `[0..0]` returned exactly the concepts that DO have the relationship | correct with `InboundRelationshipsProvider`, else an error |
| `R attr != value` | "does not have the attribute at all", the reading the forward path abandoned | correct with `InboundRelationshipsProvider`, else an error |
| `{ R attr = value }` and every other form with `R` inside braces | a set, computed on a flattened clause list against the *source* concepts' groups — so `{ R a != x }` was identical to `{ R a = x }`, `{ R a = x OR R b = y }` was empty instead of the union, and `[m..n] { R a = x }` applied a cardinality to a 1/0 pseudo-count | error |

`R attr = value` — the form `RelationshipTargets` can answer — is unchanged.

The first two are recovered by implementing the optional
`ecl.InboundRelationshipsProvider`, which supplies the inbound count and the
per-type total that a `Set` cannot carry.

The group forms are rejected on purpose, not pending. Braces assert that the
clauses hold in one relationship group **of the focus concept**, and a reverse
relationship belongs to the source, so the focus has no group to constrain. What
remains is either redundant (a lone `{ R a = x }`, measured identical to the
ungrouped form) or misleading (in `{ R a = x, b = y }` the sibling clause silently
constrains the *source*). Ontoserver refuses the construct as well, with "Cannot
reverse an attribute inside a group". Write the clause outside the braces; the
error message says so.

### 6. SCG: the default definition status is now `===`

An expression with no prefix is `equivalentTo`, per the SCG specification. It was
`subtypeOf`, which inverted the logical meaning of every unprefixed expression: a
bare precoordinated SCTID read as "some subtype of X" rather than "X".

```go
scg.Parse("22298006").DefinitionStatus
// was: "<<<"
// now: "==="
```

This changes the observable AST. If you serialize or reason over
`Expression.DefinitionStatus`, check your assumptions.

### 7. `sctid.IsValid` enforces the partition rules it documented

It checked only length, digits and the Verhoeff digit, despite the package doc
promising partition rules. It now also requires a non-zero first digit, a
partition in `{00, 01, 02, 10, 11, 12}`, and at least 11 digits for the long-form
`1x` partitions, which carry a 7-digit namespace.

```go
sctid.IsValid("000000001")   // was true, now false (leading zero)
sctid.IsConcept("100108")    // was true, now false (partition 10 needs a namespace)
```

Real SCTIDs are unaffected — the change only rejects identifiers that cannot
exist.

### 8. CLI: exit codes, and diagnostics on stderr

`-h` exited **1** with an `error: flag: help requested` prefix, and usage text and
flag errors went to **stdout**, contaminating any pipe carrying results. Both
fixed, and the exit code now carries information:

| Code | Meaning |
|---|---|
| 0 | success, including `-h` |
| 1 | runtime error |
| 2 | usage error (missing or extra argument) |
| 3 | invalid ECL syntax |
| 4 | feature not supported by this build |

Scripts that treated any non-zero exit as one failure mode still work; scripts
that parsed stdout for diagnostics need updating.

## Wrong results, now correct

Each of these produced a plausible but incorrect concept set, with no error, on
idiomatic input.

1. **`OR` inside a refinement was computed as `AND`**, so any disjunctive
   refinement returned the empty set. The parser flattened both branches into one
   slice, making the two ASTs byte-identical. Fixed at the source with a boolean
   tree (`ast.AttributeSet`), which also fixes `OR` between attribute groups,
   `OR` inside a group, and the loss of parenthesised scope — `({A} OR {B}), C`
   was indistinguishable from `{A}, ({B} OR C)`.

2. **`!=` negated the existence of the attribute, not its value.** It inverted the
   cardinality predicate, which implements `[0..0] attr = value`. The result was
   *disjoint* from the correct set, and the grouped path in the same file already
   had the right formula, so one clause got two different answers depending on
   whether it was written inside braces.

3. **Cardinality `[m..n]` was ignored on attribute groups and concrete values.**
   `AttributeGroup.Cardinality` was never read and the group loop stopped at the
   first match, so `[0..0]` — the form the ECL guide uses for absence — returned
   exactly the inverse of the requested set.

4. **`!!>` and `!!<` used direct parents and children** where the spec requires
   transitive ancestors and descendants. Wrong for any set that is not
   transitively closed, i.e. the result of a refset, a filter or a `MINUS`.

5. **Filter negation was one global flag.** Any `!=` clause flipped the whole
   conjunction, discarding its positive siblings:
   `{{ C active = false, definitionStatusId != X }}` returned active concepts.
   Concept filters are now composed per clause.

6. **Every `{{ D dialect… }}` returned the empty set.** The parser discarded the
   filter's contents and forced the operator to `=`; the evaluator then matched
   nothing and intersected. The `dialectId` form now works, including sets and
   per-entry acceptability. The alias form (`dialect = en-gb`) works too, given a
   provider implementing the optional `ecl.DialectAliasResolver`: mapping an alias
   to a language reference set's SCTID is terminology data — only the
   international English aliases are universal, and the same alias can name
   different reference sets in different editions — so it comes from the provider
   rather than a table built into this library. Without the capability the form
   reports `ErrUnsupportedFeature`, and so does an alias the provider does not
   resolve; answering it as "no dialect constraint" would widen the query to every
   dialect.

7. **`{{ M field = "literal" }}` failed at runtime** with
   `unsupported AST node type: *ast.StringValue`, despite `memberField` being
   listed as supported.

8. **Four filter branches discarded information.** `{{ D id = … }}` was skipped
   entirely — and when it was a constraint's only clause the filter node was never
   built, so the query silently returned every descendant. Escape sequences were
   never decoded, so `{{ term = "a\"b" }}` searched for the backslash too.
   Set-valued operands were flattened: a term set became one "term" with the
   parentheses included, and module, definition status, effectiveTime and
   acceptability sets kept only their first element.

9. **A provider returning `(nil, nil)`** — idiomatic Go for "nothing found" —
   panicked inside `Evaluate`. Normalized defensively, and `Evaluate` never hands
   a nil `Set` to the caller.

10. **Cancellation was never checked.** A canceled request ran to completion and
    returned a nil error. Now checked on entry and inside the per-concept loops.

11. **MRCM**: domain rows were conjoined when the refset distributes them as
    alternatives (one row per domain and contentTypeId), so a valid expression
    came back invalid; minimum cardinality was unreachable for a *missing*
    mandatory attribute, the one case it exists to catch; a rule with unparseable
    ECL aborted the whole validation and discarded the issues already found; range
    rows had the same conjunction defect as domains; and an advisory rule was
    reported as a violation.

12. **SCG rejected the specification's own example** of multiple relationship
    groups: the grammar separates groups with whitespace, and the parser required
    a comma.

13. **The reference fixture's `match` search type was `strings.Contains`**, wrong
    in both directions — `"infarction myocardial"` matched nothing (word order is
    irrelevant) and `"farct"` matched (not a word prefix). It lives in test code,
    but the README points implementors at it as the reference semantics.

## New

**Typed errors.** `errors.Is`/`errors.As` now work; previously every failure was
an `*errors.errorString` and callers could only match on message text.

```go
var pe *ecl.ParseError
switch {
case errors.As(err, &pe):                        // 400: report pe.Errors
case errors.Is(err, ecl.ErrUnsupportedFeature):  // 501
case errors.Is(err, ecl.ErrProvider):            // 503: the backend is unhealthy
}
```

**`ecl.UnimplementedDataProvider`** — embed it and implement only what you need.
Skipped methods return `ErrUnsupportedFeature` rather than the empty set, so a
partial provider reports "not supported" instead of silently answering "no
matches". It also means future methods are not a breaking change for you.

**`ecl/providertest`** — this package used to live under `internal/`, which Go
forbids importing, while the README offered it as the reference. Two entry points:

- `VerifyContract(t, newProvider)` checks the invariants against **your** data.
  It probes the provider for what it actually has, then asserts what must hold
  regardless: never return a nil `Set`, empty input yields the empty `Set`, `nil`
  sourceIDs means wildcard, the hierarchy is transitive, only `FilterConcepts` may
  filter by `active`, refset membership is invertible, the history profiles nest.
  A check your data cannot exercise is **skipped with a reason**, not failed.
- `VerifyFixture(t)` runs the 136 bundled cases against the bundled fixture,
  verifying the *evaluator*.

The suites and fixtures are embedded, so `gofhir-ecl conformance` now works from
any directory — after `go install`, it used to fail with
`no such file or directory`.

**A `DataProvider` contract in the godoc**, stating the rules the evaluator relied
on silently: non-nil `Set`s, empty input yields empty output, unordered results,
which methods are transitive, and who owns the `active` axis.

**Optional capabilities.** Some things cannot be expressed through `DataProvider`
as it stands, and widening that interface would break every implementation. They
are offered as optional interfaces the evaluator type-asserts for — the shape the
standard library uses for `io.ReaderFrom` — so implementing one is never required
and never a breaking change:

| Interface | What it unlocks |
|---|---|
| `BatchPropertiesProvider` | One query per refinement instead of one per focus concept. Measured against the bundled fixture: 27 calls → 1, same result. |
| `BatchConcreteValuesProvider` | The same for concrete-value comparisons, which otherwise cost N×T calls. |
| `InboundRelationshipsProvider` | `[m..n] R attr = value` and `R attr != value` (behaviour change 5). |
| `NegatingDescriptionProvider` | The negated description filters (behaviour change 2). |
| `DialectAliasResolver` | `{{ D dialect = en-gb }}`, whose alias-to-reference-set mapping is terminology data. |

The reference provider implements all five, so the bundled suite exercises the
paths they unlock and there is a worked example to read.
`providertest.VerifyContract` has a check per capability, asserting that it agrees
with the required method it replaces — the evaluator prefers the capability, so a
batch that disagrees with its per-concept equivalent would silently decide every
answer and nothing else would notice.

### Value sets in filters now evaluate instead of erroring

`{{ D term = ("a" "b") }}` and `{{ C effectiveTime = ("20240131" "20230731") }}`
used to report `ErrUnsupportedFeature`, because `DescriptionFilterOpts.Term` and
`ConceptFilterOpts.EffectiveTime` each carry one value.

They are any-of, so they are the union of the single-value filters, and the
evaluator now issues one provider call per value. Nothing is asked of the
provider: this works with any implementation written against the current contract.

That is deliberately preferred over adding `Terms []string` and
`EffectiveTimes []string` fields. A new field is silently ignored by every
existing provider, so the filter would quietly match on one value out of the set
and return a narrower answer than was asked for — with nothing to detect it. The
same reasoning is why `{{ D id = … }}` is still unsupported rather than given a
field.

Each call carries the sibling clauses, so the conjunction distributes correctly:
`(term = a OR term = b) AND language = es`. Each term also keeps its own match
type, so `("Diabet*" wild) ("infarction")` does not apply one term's style to the
other. Under `!=` an effectiveTime set reads "none of these" and the per-value
results are intersected rather than unioned.

**Two test suites this project did not write the expectations for.** Every
semantic expectation in the repository was authored here, which is how several of
the bugs above came to have a passing test asserting the wrong behaviour:

- **The official ECL example corpus.** The 121 expressions SNOMED International
  publishes as valid ECL are vendored under `ecl/testdata/official-examples/` and
  parsed by `TestParse_OfficialExamples`. Upstream declares them valid, so a
  failure is this library's defect by construction. All 121 pass. It settles
  syntax and says nothing about semantics.
- **A differential oracle.** `make oracle` evaluates a corpus twice: once here
  over a provider whose primitives are answered by a FHIR terminology server, and
  once by asking that server to evaluate the whole expression. The server supplies
  the facts, this library supplies only the composition — refinement, cardinality,
  negation, grouping, reverse, set algebra — which is where every semantic bug
  found so far lived. Against SNOMED CT on `r4.ontoserver.csiro.au`: 28 of 29
  cases agree, none of them vacuously. The one skip is reverse cardinality, where
  the harness implements no `InboundRelationshipsProvider` and this library
  therefore reports the construct unsupported. Neither runs during
  `go test ./...`; the oracle needs network and a divergence needs triage, not a
  red build.

`scripts/check-upstream.sh` (weekly, and `make check-upstream`) diffs the two
vendored SNOMED International artefacts — the grammar and the example corpus —
against upstream. `ecl/grammar/ECL.g4` now records where it came from, at which
commit, and the one local fix it carries: upstream references the rule as
`memberOf` on line 13 but defines `memberof` on line 14, so the grammar as
published does not generate.

**AST additions** (all additive): `ast.AttributeSet` and `ast.AttrSetOp` for the
boolean tree, `ast.SearchTerm`, `ast.DescriptionIDFilter`, `Refinement.Nested`,
and `Terms`/`Modules`/`Values`/`Acceptabilities` slices.

**CI** now runs a matrix of Go 1.24/1.25 × Linux/macOS/Windows, gates on
`go mod tidy -diff` (which failed the day it was added: `gopkg.in/yaml.v3` was
marked indirect while `internal/` imported it directly), runs the conformance
suite through the CLI, and regenerates the ANTLR parser to fail if
`ecl/grammar/` has drifted from `ECL.g4`. `make generate` pins ANTLR 4.13.2, the
version the committed parser was generated with, and reproduces it byte for byte.

**Every README snippet is now backed by a runnable `Example`**, so CI fails when
the docs and the API disagree. The SCG + MRCM snippet referenced
`mrcm.LoadModel` and `mrcm.NewValidator` — neither has ever existed.

## Deprecated

Populated as before, so nothing breaks. Removed in v2.

| Field | Use instead |
|---|---|
| `ast.Refinement.Ungrouped` | `AttrSet` |
| `ast.AttributeGroup.Attrs` | `AttrSet` |
| `ast.TermFilter.Term`, `.MatchType` | `Terms` |
| `ast.DialectEntry.Acceptability` | `Acceptabilities` |
| `ast.ModuleFilter.Module` | `Modules` |
| `ast.EffectiveTimeFilter.Value` | `Values` |
| `ast.DefinitionStatusFilter.Value` | `Values` |

The scalars cannot represent a set, and `Ungrouped`/`Attrs` cannot represent `OR`.

## Known limitations

Each returns `ecl.ErrUnsupportedFeature`, so you can classify it and answer 501
rather than serve bad data:

- Negated description filters (behaviour change 2).
- The dialect **alias** form, without a `DialectAliasResolver`; `dialectId` always
  works.
- A cardinality or `!=` on a reverse attribute, without an
  `InboundRelationshipsProvider` (behaviour change 5).
- A reverse attribute **inside an attribute group**, in any form. This one is not
  waiting on anything: braces assert that the clauses share a relationship group of
  the FOCUS concept, and a reverse relationship belongs to the source, so there is
  nothing to group. Write it outside the braces.
- `{{ D id = … }}`: the parser models it, but `DescriptionFilterOpts` has no field
  to carry the ids to the provider.
- A **negated** term filter with a set of terms — `{{ D term != ("a" "b") }}`. One
  description row has to fail every value, so it cannot be decomposed the way the
  positive form is; intersecting per-term negations would accept a concept with one
  row failing the first term and a different row failing the second.
- `^[field]` projection: `Set` carries concept IDs only. Use `{{ M … }}`.
- `AttributeDomain.InGroupCardinality` is loaded and exposed but not enforced.

Most of those are lifted by implementing an **optional capability** (see above),
not by waiting for a major version. The two that are not — `R` inside a group and
the negated term set — are decisions with reasons, recorded where the error is
raised.

## Upgrading

1. `go get -u github.com/gofhir/ecl` — it compiles; no signature changed.
2. Run `providertest.VerifyContract` against your provider. It will tell you
   whether the two contract redefinitions (behaviour changes 3 and 4) affect you.
3. Re-check any snapshot test over ECL results. If `OR`, `!=`, a cardinality, a
   dialect filter or `{{ +HISTORY }}` appears in it, the expected set has probably
   changed — and the old value was probably wrong.
4. If you validate user-supplied ECL, expect expressions that used to pass to fail
   (behaviour change 1), and classify with `errors.As` on `*ecl.ParseError`.
