# v1.6.0

The SCG package can now **produce** Compositional Grammar, not only read it.

One addition, no behaviour changes, nothing to check before upgrading.

---

## `scg.Expression.String()`

The package could parse Compositional Grammar and not render it. That is an
asymmetry in the API rather than a gap in the tests: anyone assembling a
post-coordinated expression in code — an authoring tool, a server normalizing
input before putting it in a FHIR `Coding`, anything that stores an expression it
built rather than one it received — needs to serialize.

```go
expr, _ := scg.Parse("22298006:{363698007=74281007}")
fmt.Println(expr)
// === 22298006 : { 363698007 = 74281007 }
```

The output parses back to an equal expression. That is a property, not an
aspiration: `FuzzParseRenderParse` checks it on every input the fuzzer reaches,
and CI runs it on every pull request.

`Expression` now satisfies `fmt.Stringer`, so `%v` and `%s` on one produce
Compositional Grammar instead of a Go struct dump.

## It is not "the canonical form"

The SNOMED CT glossary describes a canonical form — whitespace and terms removed,
*"focus concepts, refinements, attributes, and attribute groups in a standard
order"*. The Compositional Grammar specification **does not define that order**:
the word `canonical` appears in none of its sections.

So there is nothing to target, and this reorders nothing. What it produces is a
*faithful* rendering: same order, same terms, normalized whitespace. Two
expressions that mean the same thing but were written with their attributes in a
different order render differently, and saying otherwise would be claiming an
ordering the specification does not give. If you need a comparison key, sort before
rendering and let your own code say what the sort means.

Three choices worth knowing, all in the doc comment:

- The definition status is always emitted, `===` included. A serialization should
  mean one thing without the reader having to know which default applies.
- Terms are kept, and escaped where the grammar allows it.
- A term containing `|` is omitted rather than emitted — Compositional Grammar has
  no escape for it, so emitting it would produce text that does not parse. The
  parser cannot build such a term; only code can.

## What the round-trip property catches

Worth stating exactly, because the limits matter as much as the property.

It **catches** an asymmetry between the two halves: a value rendered without
escaping that the parser then reads as something else, a form the renderer emits
that the parser rejects, a parser that is not deterministic. That is the class that
produced a 26-byte heap-exhausting input in this repository's ECL parser in
v1.3.0.

It does **not** catch the parser silently dropping part of its input. That loss is
invisible on the second pass too, so the two agree. This compares the parser with
itself; only a corpus of expressions with known meaning compares it with the
specification, which is what the bundled conformance cases are for.

## It found two defects the day it was written

Both in the renderer, both silent, both fixed here and pinned by name in
`scg/render_test.go`.

**Nested expressions were rendered with their definition status.** The grammar
allows one on the top-level expression only, so `( === X )` does not parse — and
the parser stamps every nested expression with the `===` default, so emitting it
looked harmless until the output was fed back in.

**A whole-number decimal lost its Kind.** Compositional Grammar tells an integer
from a decimal by the decimal *point* alone, and `strconv` renders `0.0` as `"0"`,
so `#.0` came back as an **integer**. The fuzzer found it in under a second, on an
input no person would write. The exact input is in the seed corpus.

35.7M executions clean after the fix. `scg` coverage 89.9% → 91.6%.

## Also

`-fuzz` takes an unanchored regexp, so adding the second SCG target made the
existing `-fuzz FuzzParse` match two tests and fail the job. All four patterns are
anchored. The cause was not the regexp: the Makefile and the workflow were changed
and never run, and `make fuzz` would have said so in eight seconds.

## Upgrading

`go get -u github.com/gofhir/ecl`. Nothing to change — unless you print an
`scg.Expression` with `%v` and depended on seeing the struct, which now renders as
Compositional Grammar.
